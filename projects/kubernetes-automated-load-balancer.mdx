A project designing and implementing automated load balancing within a Kubernetes cluster using GitOps
practices, distributing traffic dynamically across services while keeping infrastructure as code and
deployment automated through CI and CD pipelines.

## What it established

Two things that later work depends on. First, that cluster state lives in git and reconciles toward it,
which is the position argued in
[Stop trusting events](https://www.pungrumpy.com/blog/stop-trusting-events-a-mental-model-for-reconciliation).
Second, that a rollout without monitoring attached is not finished. Synthetic checks are in the same
project as the deployment for that reason.
