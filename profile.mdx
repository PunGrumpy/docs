## What the work is about

He designs and builds software with two commitments held at once: systems that are secure and reliable
by default, and interfaces that feel considered, not just functional. In practice that means the
infrastructure work and the interface work are not separate careers. A CLI gets the same attention to
output legibility that a landing page gets to type; a Kubernetes rollout gets the same attention to
failure modes that a form gets to validation.

## Focus areas

**DevSecOps automation.** Static analysis, policy in pipelines, and making the secure path the default
path rather than the documented one. [Docker Doctor](https://www.pungrumpy.com/showcase/docker-doctor) is the clearest statement
of this: rules that score a Dockerfile instead of only complaining about it.

**Platform engineering.** Deployment workflows, authentication, and observability. Built at IBM Thailand
on GitHub Actions, OpenShift, and IBM Cloud, and independently on Kubernetes with GitOps practice.

**Design engineering.** Developer-facing products where the interface is part of the tool, not a wrapper
around it. [Verno Studio](https://www.pungrumpy.com/showcase/verno-studio) and the [client sites](https://www.pungrumpy.com/showcase) sit here.

**Terminal tooling.** Small, sharp CLIs in Go and TypeScript. Most of the 2026 project run began as a
command someone wanted to stop retyping.
